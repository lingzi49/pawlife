> **说明**：本报告记录本轮 P0/P1 修复后的状态。旧版 AUDIT 基于提交 `fcb98e0`，其 15 枚勋章、14 条保健品规则、46 个 API、14 天暂停和旧 RER 公式均已过时，不应继续引用。

## 1. 审计范围与结论

本轮审计覆盖：

- 原始 Web 应用的页面、API、规则、数据模型、依赖和启动方式；
- Showcase 的页面结构、数据来源和与原始应用的差异；
- 小程序的前后端结构、数据隔离和完成度；
- README、TECHNICAL_DETAILS、AUDIT 的事实一致性；
- 审计中发现的核心问题修复与回归验证。

结论摘要：

- **P0-1 高风险提示已修复**：异常行为表单新增补充描述，前后端使用同一套风险词表和同义表达；服务端不再只信任前端 `high_risk`。
- **P0-2 访问边界已部分收紧**：CORS 默认不开放跨域，可通过 `ALLOWED_ORIGINS` 显式配置；认证和多用户隔离仍未实现，项目仍只适合本地单用户使用。
- **P0-3 疫苗周期已统一**：后端 `VACCINE_REMINDER_DAYS`（默认 1095 天）通过 `/api/health_check` 返回，前端读取同一参数；该值是项目提醒参数，不是医学标准。
- **P1-1 每日任务入口已接通**：高光时刻页新增任务卡，体重任务跳转已修正，任务完成会走现有防重复逻辑。
- **P1-2 每日提示已统一**：首页提示卡调用 `/api/daily_tip`；重复的前端提示数组已移除。
- **P1-3 性别枚举已统一**：提醒页改用 `female`，发情提醒可显示。
- **P1-4 事件派生状态已部分修复**：洗澡日期、风险暂停、健康相册引用会在编辑/删除后重算；勋章和爪印按成就记录保留，不回滚。
- **P1-5 健康照片入口已补齐**：首页新增健康成长相册展示和删除；头像盲盒管理入口仍未完整接入。
- 仍存在单用户限制、无认证、无数据库外键、进程内幂等缓存、测验答案暴露、Google Fonts 外部请求等问题。

## 2. 本轮已修复的问题

<a id="a1"></a>
### A1. Web 端高风险提示无法命中（已修复）

- **原问题**：异常行为表单只有 6 个短症状复选项，没有自由文本；31 个高风险词均不是这些选项的子串，实际无法触发提示。
- **修复**：
  - 异常行为表单新增“补充描述”文本框；
  - 前端把症状和描述合并扫描 `HIGH_RISK_SYMPTOMS` 与 `HIGH_RISK_SYNONYMS`；
  - 服务端 `_scan_high_risk_text()` 在创建/编辑事件时独立再扫描，不依赖前端是否传 `high_risk`；
  - 增加“一直吐 / 拉血 / 抽风 / 喘不上气”等少量同义表达，普通症状仍不自动升级；
  - 高风险记录继续写入风险日志和暂停状态。
- **代码位置**：`pawlife_web.py` 的 `HIGH_RISK_SYNONYMS`、`_scan_high_risk_text`、`_event_risk_text`、`api_create_event`、`api_update_event`；前端 `renderExtraFields`、事件提交和风险确认逻辑。
- **验证**：普通描述“偶尔抓痒，精神正常”不弹窗；描述“今天持续呕吐两次”弹出提示并暂停建议；服务端单独提交 `high_risk=0` 的同义表达也能识别。
- **状态**：已修复（代码 + 浏览器验证）

### A3. 疫苗提醒周期不一致（已修复）

- **原问题**：提醒页使用 365 天，`/api/health_check` 使用 1095 天。
- **修复**：新增 `VACCINE_REMINDER_DAYS`（环境变量可配置，默认 1095）；后端统一计算并在 `/api/health_check` 返回 `vaccine_reminder_days`；前端提醒页读取该值，不再维护 365 天常量。
- **边界**：该值是项目提醒参数，不宣称是统一医学标准；不同疫苗的免疫计划应由兽医制定。
- **代码位置**：`pawlife_web.py` 常量区、`api_health_check`、前端 `loadRemindersPage`。
- **验证**：`/api/health_check` 返回 `vaccine_reminder_days=1095`；前端提醒页使用返回值。
- **状态**：已修复（代码 + API 验证）

### A4. 每日任务入口（已修复）

- **原问题**：后端有 17 条任务和完成接口，但页面没有任务卡 DOM，`loadTask()` 未被调用。
- **修复**：高光时刻页新增任务卡；进入 badges 页时调用 `loadTask()`；体重任务改为跳转到身材管理并聚焦体重输入；任务完成 UI 对不在当前页面的情况做了空值保护。
- **验证**：任务卡可加载；点击体重任务后到达身材管理页；录入体重后任务状态变为已完成，且无控制台错误。
- **状态**：已修复（代码 + 浏览器验证）

### A5. 每日提示数据源（已修复）

- **原问题**：后端 `/api/daily_tip` 未被调用，前端另有约 89 条未使用提示数组。
- **修复**：首页新增“今日养宠提示”卡片并调用 `/api/daily_tip`；移除未使用的前端 `DAILY_TIPS` 数组和函数，避免两套内容继续漂移。
- **验证**：首页提示文本成功加载；未发现旧数组引用。
- **状态**：已修复（代码 + 浏览器验证）

### A6. 性别枚举不一致（已修复）

- **原问题**：提醒页使用 `_cachedDog.gender === '母'`，API 返回 `female`，发情提醒分支不显示。
- **修复**：改为 `=== 'female'`。
- **验证**：写入一条发情事件后，提醒页显示“发情记录”。
- **状态**：已修复（代码 + 浏览器验证）

### A11. 删除事件后的健康相册引用（已修复）

- **原问题**：删除事件会删除照片文件，但不清理 `dogs.health_photos` 中的引用。
- **修复**：新增 `_remove_health_photo_reference()`，删除事件时同步移除对应相册条目。
- **状态**：已修复（代码）

## 3. 部分修复或仍存在的问题

### A2. Web 端没有认证、权限和数据隔离（部分修复）

- **本轮变化**：CORS 默认不再允许任意来源，只允许同源访问；确需跨域时通过 `ALLOWED_ORIGINS` 显式配置。
- **仍存在**：所有 Web API 仍是匿名访问，没有登录、用户归属或权限校验；照片、导出和数据库操作也没有权限边界。
- **影响**：只适合本地单用户原型。公网部署前必须增加认证、授权、HTTPS 和访问控制，不能仅靠收紧 CORS 解决。
- **状态**：部分修复（CORS 已收紧；认证未实现）

### A7. 事件编辑/删除的派生状态（部分修复）

- **已修复**：
  - 编辑事件会重新扫描风险并更新 `high_risk` / `risk_keyword`；
  - 编辑或删除洗澡事件会重算 `last_bath_date`；
  - 删除事件会重算风险暂停并清理健康相册引用；
  - 创建事件先 `flush()`，确保返回有效的 `event_id`。
- **保留设计**：`risk_logs` 作为历史审计记录保留，不随编辑/删除重写；勋章和爪印按成就记录保留，不因删除事件回滚；任务完成状态由签到表维护，不随事件删除回滚。
- **仍存在**：没有独立的事件变更服务；后续如果增加更多派生字段，需要继续集中处理。
- **状态**：部分修复（派生日期/风险/照片已处理，成就按设计不回滚）

### A9. 照片管理入口（部分修复）

- **已修复**：首页新增健康成长相册，展示 `health_photos`，点击照片可删除；页面加载时会刷新相册。
- **仍存在**：头像盲盒/肉垫影集有上传、删除和每日头像接口，但页面没有完整的盲盒上传/管理入口。
- **状态**：部分修复（健康相册已接入；盲盒管理未接入）

<a id="a10"></a>
### A10. 签到里程碑与勋章墙口径（仍存在）

- **问题**：7/14/30/60 天里程碑把字符串追加到 `dogs.badges`；`/api/badges` 的 `total_unlocked` 统计所有条目，但勋章墙只遍历 16 个定义。
- **影响**：可能出现“已收集数量大于墙上可见勋章”的显示差异。
- **状态**：仍存在（未改数据结构）

### A8. 单用户、单狗狗、无数据隔离（仍存在）

- **问题**：Web 端默认操作“最新创建的一只狗狗”，没有多宠物切换、用户账号或租户字段。
- **状态**：仍存在（设计限制）

## 5. 潜在风险（不是已确认缺陷）

- **健康建议风险**：RER/DER、食谱、保健品和风险提示是规则或项目参数，不能替代兽医诊断；边界情况可能不适合个体宠物。
- **数据丢失风险**：SQLite 本地文件没有备份/恢复机制；照片和数据库都在本地目录。
- **公开暴露风险**：没有认证和权限控制；即使 CORS 默认关闭，LAN 或直接访问仍可能读写数据。
- **第三方资源风险**：Google Fonts 请求可能失败或被拦截，也会产生第三方请求。
- **照片存储增长**：照片以文件或 Base64 存在本地，没有容量配额或清理策略。
- **文档漂移风险**：历史兽医审查材料和代码行号会继续变化；引用时应标注基线。

## 8. 建议优先级

1. **P0（公网部署前）**：增加认证、权限、数据隔离和 HTTPS；不要把当前 Web 应用直接暴露到公网。
2. **P1（一致性/维护性）**：统一签到里程碑与勋章数据结构（A10）；补齐头像盲盒管理入口（A9）；统一错误响应（A15）。
3. **P2（工程质量）**：增加 API/数据库测试和浏览器回归；处理数据库外键/迁移方案（A13）；评估进程外幂等存储（A14）。
4. **P3（产品边界）**：明确 CSV 导出范围（A19）；处理 Google Fonts 依赖（A18）；继续由专业人员审核健康规则。
