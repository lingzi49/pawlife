## 1. 产品概述

PawLife 是一款面向新手宠物主的狗狗健康管理网页应用。核心价值主张：

- **降低焦虑**: 用狗狗第一人称口吻提供情绪安抚
- **科学指导**: 基于品种、年龄、体重提供个性化饮食/保健品/疫苗/驱虫建议
- **游戏化激励**: 爪印积分 + 15 枚勋章系统鼓励持续健康管理
- **风险预警**: 31 个高危症状关键词自动检测并拦截，引导就医

### 用户画像

- 首次养狗的新手铲屎官
- 需要简单直观的健康追踪工具
- 对兽医术语不熟悉，需要通俗化解释

## 2. 系统架构

### 2.1 文件结构

```
pawlife_web.py          ← 唯一应用文件
├── [行 1-20]          模块文档字符串
├── [行 22-89]         导入 + 自动依赖安装 + 数据库设置
├── [行 92-206]        8 个 SQLAlchemy ORM 模型
├── [行 212-256]       init_db() 建表 + 列迁移
├── [行 258-304]       FakeRedis 幂等存储
├── [行 309-536]       常量与验证模型 (品种列表/勋章定义/生存指南/测验/任务)
├── [行 538-614]       Pydantic 请求模式
├── [行 616-887]       业务逻辑 (决策树/行为分析/第一人称反应)
├── [行 889-936]       FastAPI 应用 + CORS + 数据库会话
├── [行 939-968]       演示数据创建
├── [行 971-1155]      爪印积分/勋章/辅助函数
├── [行 1157-3706]     46 个 API 端点
├── [行 3717-11093]    内嵌 HTML/CSS/JS (~7,376 行前端代码)
└── [行 11096-11141]   服务器启动入口
```

### 2.2 部署架构

- **本地**: `python pawlife_web.py` → uvicorn 启动 → 自动打开浏览器
- **云端**: 通过 `DATA_DIR` 环境变量指定持久化目录，支持 Fly.io / Render 部署
- **端口**: 默认 8000，可通过 `PORT` 环境变量覆盖
- **单用户模型**: 所有端点使用 `Dog.created_at.desc().first()` 获取唯一狗狗

### 2.3 关键技术决策

| 决策 | 原因 |
|------|------|
| 单文件架构 | 降低部署复杂度，适合个人项目 |
| SQLite | 零配置嵌入式数据库 |
| FakeRedis (内存) | 避免引入 Redis 依赖，5 分钟 TTL 防重 |
| 内嵌前端 | 无构建步骤，单一部署单元 |
| 无认证 | 单用户场景，个人本地使用 |

## 3. 功能模块清单

### 模块 1: 狗狗建档
- **入口**: 首次访问自动弹出建档弹窗
- **字段**: 名字(必填)、品种(必填)、生日(必填)、性别、体重、绝育状态、到家日期、过敏源、疾病史
- **自动操作**: 创建后同步首条体重记录、刷新保健品推荐、检查勋章
- **编辑**: 通过首页档案卡"编辑"按钮或头像点击

### 模块 2: 首页仪表盘
- **今日状态条**: 头像 + 名字 + 品种 + 年龄 + 爪印积分 + 签到天数
- **每日健康检查**: 折叠卡片，按日期轮换检查提示，正常/异常两种结果
- **功能入口网格**: 记录事件、饮食宝典、照护提醒、成长记录、荣誉勋章、保健品小队、每日任务、体重管理
- **健康档案卡**: 标签式展示关键健康指标（体重/BMI/BCS/疫苗/驱虫/洗澡/发情/过敏源/疾病）
- **成长记录摘要**: 最新体重趋势和年龄阶段

### 模块 3: 事件记录
- **事件类型**: 疫苗、驱虫、发情、异常行为、洗澡澡
- **幂等防重**: 基于事件类型+日期的幂等键，5 分钟内不可重复提交
- **高风险检测**: 31 个高危症状词触发紧急警告（如"吐血""抽搐""瘫痪"）
- **第一人称反应**: 每类事件生成狗狗口吻的安抚/鼓励回复
- **照片上传**: 支持事件关联照片，异常行为可上传症状照

### 模块 4: 汪生时间线
- **展示**: 按日期倒序展示所有事件，带类型图标和颜色
- **筛选**: 按事件类型过滤（全部/疫苗/驱虫/发情/异常/洗澡）
- **操作**: 编辑、删除、上传照片
- **兽医摘要**: 异常行为事件可生成就诊摘要卡片（含症状、时间线、品种信息）

### 模块 5: 饮食宝典
- **个性化计算**: RER(70×W^0.75) → DER(×活动系数×性别系数) → 每日喂食克数(/1.5kcal/g)
- **食材推荐**: 9 种（年龄阶段 × 体型）的食材组合
- **营养分析**: 蛋白质/脂肪/碳水克数和热量占比
- **过敏过滤**: 自动排除过敏食材并提供替代
- **计算依据**: 展示 RER→DER 完整计算链条

### 模块 6: 体重管理
- **记录**: 体重数值 + 日期
- **趋势图**: SVG 折线图，支持 30/90/180/365 天范围
- **统计**: 最低/最高/平均/最新/变化量
- **BCS 体况评估**: thin/ideal/heavy 三档，触摸式评估指引
- **滑动删除**: 移动端左滑删除，桌面端右键菜单

### 模块 7: 保健品小队
- **规则引擎**: 14 条规则（年龄/体重/皮毛/关节/肠胃/心脏/泌尿/肝脏/免疫/情绪/皮肤/寄生虫/口腔/BCS）
- **季节感知**: 夏季增补 Omega-3，冬季增补维生素D
- **病史增强**: 根据狗狗已知疾病增强推荐
- **高风险暂停**: 异常行为触发高风险关键词后暂停所有保健品推荐
- **空状态**: 无推荐时展示评估依据和引导操作

### 模块 8: 荣誉勋章
- **勋章数量**: 15 枚，分 3 个分类（第一次/守护者/健康里程碑）
- **解锁条件**: 自动检测（记录事件后、签到后、体重更新后、任务完成后）
- **展示**: 已解锁/未解锁两态，含解锁日期和故事
- **进度条**: 已解锁数/总数 百分比
- **下一枚推荐**: 最接近解锁条件的勋章 + 引导操作

### 模块 9: 照护提醒
- **数据源**: 客户端计算（疫苗/驱虫/发情/体重）+ 服务端补充（洗澡/保健品/BCS）
- **显示**: 天数倒计时 + 状态标签 + 操作引导按钮
- **自动更新**: 首页待办计数实时同步

### 模块 10: 每日签到
- **签到**: 每日一次，+1 爪印
- **连续签到**: 追踪连续天数
- **里程碑**: 7/14/30/60 天奖励 + 勋章检测
- **自动补签**: 完成任务时若未签到自动补签

### 模块 11: 每日任务
- **任务池**: 17 个任务，按日期确定性轮换
- **类型**: 导航型（跳转到指定页面）、确认型（询问是否完成）、拍照型（引导上传照片）
- **奖励**: +2 爪印，自动补签

### 模块 12: 彩蛋测验
- **题目**: 10 道狗狗知识问答
- **出现位置**: 保健品页面，每日确定性选取
- **奖励**: +2 爪印（每日限 1 次）
- **可见性**: 答对后当日隐藏入口

### 模块 13: 健康相册
- **照片来源**: 事件关联照片、异常行为症状照
- **展示**: 胶片条式缩略图，点击全屏查看
- **删除**: 支持单张删除确认

### 模块 14: 头像盲盒
- **机制**: 每天从健康照片中加权随机选取一张作为首页头像
- **影集**: 最多 6 张 Base64 照片
- **切换**: 每日自动更换头像索引

### 模块 15: 成长记录
- **首页摘要**: 体重趋势 + 年龄阶段 + 到家天数
- **空状态**: 无体重记录时引导记录

### 模块 16: 数据导出
- **格式**: CSV（Excel 友好，UTF-8 BOM）
- **内容**: 狗狗档案 + 事件列表 + 体重记录 + BCS 记录 + 签到记录 + 爪印历史

### 模块 17: 到家周年
- **检测**: 首页加载时自动检查到家日期
- **报告**: 弹出周年报告（天数、事件统计、体重变化、勋章数）

## 7. 业务逻辑规则

### 7.1 年龄判定
- **幼犬**: ≤12 个月（大型犬 ≤18 个月）
- **成犬**: 12 个月 ~ 7 岁（大型犬 ~ 5 岁）
- **老年犬**: >7 岁（大型犬 >5 岁）

### 7.2 驱虫间隔
- 幼犬: 30 天
- 成犬: 90 天

### 7.3 疫苗提醒
- 幼犬首年: 3 针基础疫苗(间隔 21-28 天) + 1 针狂犬
- 成犬: 每年 1 次加强针

### 7.4 洗澡间隔
- 短鼻犬(法斗/巴哥/英斗): 更勤(14-21 天)
- 双层毛(柴犬/柯基/哈士奇/金毛/萨摩耶): 更疏(30-45 天)
- 其他: 21-30 天

### 7.5 饮食计算
```
RER = 70 × (体重kg)^0.75
活动系数: 幼犬1.6, 成犬1.4, 老年犬1.2
性别系数: 绝育0.95, 未绝育公犬1.0, 未绝育母犬0.9
DER = RER × 活动系数 × 性别系数
每日喂食克数 = DER / 1.5 kcal/g
```

### 7.6 BCS 评估间隔
- 偏瘦/偏胖: 14 天复查
- 理想: 30 天复查

### 7.7 高风险规则
- 命中 31 个高危词中任意一个 → 标记 high_risk
- 饮食推荐暂停 14 天
- 保健品推荐暂停 14 天
- 用户可手动解除暂停

### 7.8 签到与连续
- 每日签到: +1 爪印
- 连续签到重置: 超过 1 天未签到
- 自动补签: 完成任务时若今日未签到

### 7.9 爪印积分获取
| 操作 | 积分 | 频率限制 |
|------|------|----------|
| 签到 | +1 | 每日 1 次 |
| 完成任务 | +2 | 每日 1 次 |
| 答对测验 | +2 | 每日 1 次 |
| 记录事件 | +1 | 无限制(幂等5分钟内) |

### 7.10 勋章解锁条件（15 枚）

**分类: 第一次 (5 枚)**
1. 初次见面 — 完成狗狗建档
2. 第一次记录 — 记录第一个事件
3. 第一次体检 — 记录第一次体重
4. 第一次签到 — 完成第一次签到
5. 第一次任务 — 完成第一个任务

**分类: 守护者 (5 枚)**
6. 疫苗守护者 — 完成所有基础疫苗
7. 驱虫守护者 — 完成 3 次驱虫
8. 体重管理者 — 记录 5 次体重
9. 连续签到 7 天 — 连续签到 7 天
10. 知识达人 — 答对 5 道测验

**分类: 健康里程碑 (5 枚)**
11. 体重达标 — 体重进入品种理想范围
12. 连续签到 30 天 — 连续签到 30 天
13. 完美档案 — 填写所有档案字段
14. 洗澡达人 — 记录 5 次洗澡
15. BCS 理想 — BCS 评估为 ideal

## 10. 错误处理

### 10.1 HTTP 异常处理器
- **500**: 全局异常捕获 → 返回 `{"error": "内部错误", "detail": str(e)}`
- **404**: 自定义 404 页面 → `{"error": "页面不存在"}`
- **400**: 参数校验失败 → `{"error": "参数错误", "detail": ...}`

### 10.2 前端错误处理
- `api()` 函数统一捕获 fetch 异常并显示 Toast
- 网络错误: "网络连接失败，请检查网络"
- 服务端错误: 显示返回的 error 消息
- 超时: 默认浏览器超时

### 10.3 数据库错误
- `init_db()` 使用 try/except 静默处理列迁移失败
- 数据库文件自动创建
- 外键约束默认关闭(SQLite 默认)

### 10.4 幂等性保护
- FakeRedis 内存存储，5 分钟 TTL
- 处理中占位符 30 秒
- 冲突时返回 409: "请勿在 5 分钟内重复记录相同事件"

## 11. 关键假设与约定

### 11.1 产品假设
1. **单狗家庭**: 系统设计为单只狗狗使用，所有 API 取最新创建的狗
2. **主人即用户**: 无需多用户/权限系统
3. **本地使用优先**: SQLite + 内存 FakeRedis，适合个人本地使用

### 11.2 数据假设
1. **体重可解析**: 存储为字符串但业务逻辑中解析为数字
2. **品种在列表中**: BREED_OPTIONS 覆盖 34 个常见品种
3. **日期格式**: 统一使用 ISO 格式 (YYYY-MM-DD)
4. **过敏源逗号分隔**: 存储和解析均使用逗号分隔

### 11.3 技术假设
1. **Python 3.8+**: 依赖 f-string 和类型注解
2. **现代浏览器**: 使用 CSS Grid/Flexbox/Custom Properties/Fetch API
3. **UTF-8 编码**: 前端和后端均使用 UTF-8
4. **单进程运行**: FakeRedis 为内存存储，不支持多进程
5. **依赖自动安装**: `_ensure_deps()` 在导入失败时自动 pip install

### 11.4 业务假设
1. **疫苗类型固定**: 犬四联/六联/八联 + 狂犬
2. **驱虫频率按年龄**: 幼犬 30 天/成犬 90 天
3. **洗澡频率按品种**: 短鼻犬更勤，双层毛更疏
4. **饮食基于商业狗粮**: 1.5 kcal/g 为商业干粮平均热量密度
5. **BCS 主观评估**: 依赖用户触摸肋骨自我判断
